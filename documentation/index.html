DreamDay – Wedding Planner Website HTML Template

Thank you for purchasing DreamDay. This document explains how the template is organised, how to edit its pages, and how to change its colors, fonts, light and dark mode, text direction and behaviour. Every section can be read on its own, so feel free to jump straight to the topic you need.

  • 9 HTML pages
  • Bootstrap 5
  • Vanilla JS (no jQuery)
  • SCSS source
  • RTL ready
  • Light & dark mode
Item name
DreamDay – Wedding Planner Website HTML Template
Version
1.0.0
Author
Laralink
Stack
HTML5, Bootstrap 5.3, SCSS, plain JavaScript
No build step needed. Open any .html file and edit the text and images directly. The compiled assets/css/style.css is ready to use; the SCSS source is included only if you prefer to work with it.

Features

  • 9 pages Home, About, Services, Service Details, Packages, Contact, Privacy Policy, Terms & Conditions and 404.
  • Bootstrap 5.3 Grid and utilities from Bootstrap, with the theme styles in one style.css.
  • Plain JavaScript One main.js, no jQuery. Every feature is a small, commented function.
  • Organised SCSS Partials per section, CSS custom properties for colors and fonts, modern @use syntax.
  • Fully responsive Layouts checked from 320px phones to large desktops.
  • RTL from the same CSS Switch dir="rtl" and the whole layout mirrors. No second stylesheet.
  • Light & dark mode Visitors pick Device, Light or Dark (and LTR / RTL) from a small switcher on the side of every page.
  • Working contact form Sends messages through Web3Forms, with no server code needed.
  • Sliders & lightbox Swiper sliders set up with data attributes, and a GLightbox image gallery.
  • Animated counters Digits roll like a slot machine when the numbers scroll into view.
  • Scroll animations Headings and images fade in with AOS, and Lenis gives smooth scrolling.
  • Accessible markup Skip link, labelled controls, keyboard support and reduced-motion support.

Requirements

Class names start with cs_ so they never clash with Bootstrap. Section styles are named cs_<section>_style_<N>: for example cs_hero_style_1 is the home hero and cs_hero_style_2 the inner-page hero. The number only tells designs apart.

Installation

  1. Unzip the download and open the template folder in your editor.
  2. Open any .html file in your browser to preview it. For the map, video and contact form, start a local server, for example with the VS Code Live Server extension.
  3. Edit the text and images in the HTML files. Colors and fonts are set once in assets/css/style.css (see Colors).
  4. Add your Web3Forms key to contact.html so the contact form can send messages (see Forms).

npm scripts (optional)

Only needed if you edit the SCSS. Run npm install once in the template folder, then:

CommandWhat it does
npm run build:cssCompiles assets/sass/style.scss into assets/css/style.css once.
npm run watch:cssRecompiles style.css every time you save an SCSS file.

Deployment

DreamDay is a static site, so it runs on any web host. Upload the HTML files and the assets/ folder to your server (for example into public_html/) with FTP or your host's file manager. No database or server language is needed.

Compile the CSS before you upload

If you edited any .scss file, make sure assets/css/style.css is up to date first, because the browser only reads the CSS file. If you use the VS Code Live Sass Compiler extension, it already compiles on every save. If you don't have it installed, compile with npm:

  1. Install Node.js 18 or newer (once).
  2. Open a terminal in the template folder and install the Sass compiler (once): 
    npm install
  3. Build the CSS: 
    npm run build:css
    This writes the compiled styles to assets/css/style.css.
  4. Upload the files listed below.
If you only edited the HTML or style.css directly, skip the build and upload right away.
File or folderUpload?
*.html, assets/css, assets/js, assets/fonts, assets/imgYes
assets/sass/, package.json, package-lock.json, node_modules/No, only used to compile the SCSS
All links between pages are relative (about.html, assets/img/…), so the site also works from a sub-folder such as example.com/wedding/ without changes.

Page Anatomy

Every page follows the same order: the theme script in the <head>, then the preloader, header, the page sections inside <main>, the footer, the back-to-top button and the scripts. Shortened: 

<!DOCTYPE html>
<html lang="en" class="no-js">
  <head>
    <meta charset="UTF-8">
    <script src="assets/js/theme-init.js"></script>
    <!-- meta, favicon, Google Fonts, CSS files -->
    <title>DreamDay - Wedding Planner Website HTML Template</title>
  </head>
  <body>
    <a class="cs_skip_link" href="#main">Skip to main content</a>
    <div class="cs_preloader">…</div>
    <header class="cs_site_header_style_1 cs_sticky_header">…</header>
    <main id="main">
      <section class="cs_hero_style_1">…</section>
      <section class="cs_about_style_1">…</section>
    </main>
    <footer class="cs_footer_style_1">…</footer>
    <button class="cs_scrolltop_btn">…</button>
    <script src="assets/js/glightbox.min.js"></script>
    <script src="assets/js/swiper.min.js"></script>
    <script src="assets/js/lenis.min.js"></script>
    <script src="assets/js/aos.min.js"></script>
    <script src="assets/js/main.js"></script>
  </body>
</html>
  • Each section is wrapped in <!-- Start … --> / <!-- End … --> comments, so you can find, copy, move or delete it easily.
  • Any section can be copied to another page; its styles are global.
  • Change the <title> and <meta name="description"> of every page for search engines.

Creating a new page

  1. Copy the page closest to what you need, for example about.html, and rename it (gallery.html).
  2. Update its <title>, meta description and the heading in the page hero.
  3. Keep the sections you want inside <main> and delete the rest.
  4. Link to it from the menu of every page (see Header & Menu).

Header & Menu

The header has the logo in the centre and the menu split into two lists, one on each side. The menu is plain HTML, repeated in every page, so update it in all .html files.

Adding a menu item

<ul class="cs_nav_list cs_mp_0">
  <li><a href="packages.html">Packages</a></li>
  <li><a href="gallery.html">Gallery</a></li>
  <li><a href="contact.html">Contact</a></li>
</ul>

Keep both lists about the same length so the logo stays centred.

Mobile menu

Below 1200px the two lists join into one mobile menu behind a toggle button. It closes on Esc, on a link click and when the window grows back to desktop width. The breakpoint is MOBILE_MENU_BREAKPOINT in assets/js/main.js and must match the max-width: 1199px rule in assets/sass/common/_header.scss.

Sticky header

Headers with the cs_sticky_header class stick to the top once the page scrolls. Remove the class to keep the header in place.

Footer

The footer (cs_footer_style_1) has a call-to-action heading with social links, three link columns (About, Service, Contact) and a bottom bar with the copyright and legal links. Edit the links, phone number and email in every page. The copyright year in <span class="cs_getting_year"> updates itself to the current year. 

<li><a href="tel:+15550123456">+1&nbsp;(555)&nbsp;012&#8209;3456</a></li>
<li><a href="mailto:hello@example.com">hello@example.com</a></li>

Social links use short labels (TW, FB, IG) with an aria-label. Change the href to your profile and keep the label descriptive.

Colors & Dark Mode

All colors are CSS custom properties at the top of assets/css/style.css (source: assets/sass/default/_variable.scss). Change a value once and every page follows. 

:root {
  --white-color: #fff;
  --black-color: #000;
  --primary-color: #6C4E3F;   /* brown: text, buttons, borders */
  --secondary-color: #FAF6F2; /* cream: page background */
  --gray-color: #F3EEE7;      /* soft section background */
  --surface-color: #fff;      /* header, mobile menu, photo frames */
  --brand-color: #6C4E3F;     /* brown that stays brown in dark mode */
  --on-brand-color: #FAF6F2;  /* text on brown */
}
  • Primary #6C4E3F
  • Secondary #FAF6F2
  • Gray #F3EEE7
  • Surface #FFFFFF
  • Black #000000
Keep a contrast ratio of at least 4.5:1 between --primary-color and --secondary-color so text stays readable.

Dark mode

The switcher on the side of every page (bottom corner on phones) cycles Device (the default, follows the visitor's system setting) → Light → Dark. The choice is saved in the browser (dreamday-theme in localStorage) and set on the page as <html data-theme="dark">. assets/js/theme-init.js applies it in the <head> before the first paint, so the page does not flash.

Dark mode only swaps the color variables. Change the dark values in _variable.scss (or near the top of style.css): 

[data-theme="dark"] {
  --primary-color: #E8D9CB;   /* text, headings, borders */
  --secondary-color: #16110E; /* page background */
  --gray-color: #211915;      /* soft section background */
  --surface-color: #2A211C;   /* header, mobile menu, photo frames */
  --surface-translucent: rgba(42, 33, 28, 0.88);
  --hover-strong-color: #fff;
}
  • Brown line-art images (flowers, icons, logo) are lightened automatically, and the two light background images switch to their _dark.webp versions. See assets/sass/common/_theme.scss.
  • Link straight to a theme with a URL parameter: index.html?theme=dark, ?theme=light or ?theme=system.
  • To make dark the default for everyone, add data-theme="dark" to the <html> tag of each page.
  • To hide the switcher, delete the line themeSwitcher(); inside the DOMContentLoaded block of assets/js/main.js. Saved choices and URL parameters still work through theme-init.js; remove that script tag from the <head> too if you don't want them.

Changing a font

  1. Pick a font on Google Fonts and copy its <link> URL.
  2. Replace the Google Fonts <link> in the <head> of every page.
  3. Change the family name in --primary-font or --secondary-font in style.css (or _variable.scss).
For Arabic, Hebrew, Cyrillic or other scripts, choose a font that supports them (see RTL Support).

Icons

UI icons come from Font Awesome Free 7, self-hosted in assets/fonts/ and loaded with assets/css/fontawesome.min.css. Pick an icon on their site and copy its class: 

<i class="fa-regular fa-heart"></i>
<i class="fa-solid fa-chevron-up"></i>
<i class="fa-brands fa-instagram"></i>
  • Icons take the text color and font size of their parent.
  • An icon-only link or button needs an aria-label that says what it does, and the icon itself aria-hidden="true".
  • Decorative illustrations (flowers, ornaments, package icons) are SVG files in assets/img/. Replace them with files of the same name.

Logo & Images

Logo

Replace assets/img/logo.svg (header) and assets/img/logo2.svg (footer). Keep a similar wide shape so it fits the header, or update the width and height on the <img> in each page.

Favicon

Replace assets/img/favicon.png with your own square icon (32×32 or larger) and keep the name.

Replacing images

The simplest way is to overwrite a file in assets/img/ with your own image of the same name and a similar shape.

  • Always write a short alt text that describes the new photo. Use alt="" for purely decorative images.
  • Export photos at about 1.5× their displayed size and save them as WebP (quality ~80) to keep pages fast.
  • If you use another format, update the file extension in the HTML.

Background images

Section backgrounds use a data-src attribute, which main.js turns into a CSS background: 

<section class="cs_hero_style_2 cs_bg_filled" data-src="assets/img/service_hero.webp">
Demo photos are for preview only and are replaced with placeholders of the same size and name in the download. See Credits.

Spacing

Vertical space between sections is an empty <div> with two classes: the height on desktop and the height on tablets and phones (below 992px).

Editing the SCSS

You can edit assets/css/style.css directly. If you prefer SCSS, install Node.js, then run in the template folder: 

npm install
npm run watch:css

Prefer not to use the terminal? The VS Code Live Sass Compiler extension does the same job: set its output to assets/css/style.css and click Watch Sass. Without it, run npm run build:css before you upload (see Deployment).

assets/sass/style.scss loads the partials in order and has a table of contents at the top. The SCSS uses the modern @use syntax and compiles without warnings on Dart Sass 1.80+.

Compiling overwrites assets/css/style.css. Pick one way of working: if you edit the CSS file by hand, those changes are lost the next time you compile the SCSS.

RTL Support

Every page supports right-to-left languages from the same stylesheet. Set the direction on the <html> tag of each page: 

<html lang="ar" dir="rtl" class="no-js">

Visitors can also switch between LTR and RTL in the switcher. Their choice is saved in the browser (dreamday-dir in localStorage), and you can link straight to it with index.html?dir=rtl (also ?dir=rtl&theme=dark).

The theme CSS uses logical properties, so the layout mirrors automatically. When you add your own CSS, keep it direction-agnostic:

UseInstead of
margin-inline-start / -endmargin-left / margin-right
padding-inline-start / -endpadding-left / padding-right
inset-inline-start / -endleft / right
text-align: start / endtext-align: left / right
Bootstrap ms-* / me-*, text-start / text-endml-* / mr-*
  • Numbers, prices and phone numbers always stay left-to-right.
  • Transforms do not flip on their own. Add a [dir="rtl"] rule for them, as in assets/sass/common/_theme.scss.
Cormorant Upright and Montserrat cover Latin scripts only. For an Arabic, Hebrew or Persian site, also load a suitable font (see Changing a font).

Components

Interactive parts are set up in assets/js/main.js from classes and data attributes, so you only write HTML.

Sliders

Sliders use Swiper. A .cs_slider wraps a .cs_slider_container whose data attributes hold the options: 

<div class="cs_slider">
  <div class="cs_slider_container" data-autoplay="0" data-loop="1" data-speed="600"
    data-slides-per-view="responsive" data-xs-slides="1" data-sm-slides="1"
    data-md-slides="2" data-lg-slides="3">
    <div class="swiper-wrapper">
      <div class="swiper-slide">…</div>
    </div>
  </div>
</div>
AttributeDescription
data-autoplay0 = off, 1 = on, or a delay in ms (e.g. 5000)
data-loop1 to loop slides
data-speedTransition speed in ms
data-slides-per-viewA number, or responsive to use the next four attributes
data-xs/sm/md/lg-slidesSlides shown at 0 / 640 / 768 / 1024px and up

Autoplay stops when the visitor prefers reduced motion.

Counters

<span class="cs_counter" data-count-to="250" data-suffix="+">250+</span>

When the counter scrolls into view, the digits roll like a slot machine and stop on the final number. Under reduced motion the number appears at once.

AttributeDescription
data-count-toFinal number. Decimals and commas are supported (96.8, 1,200).
data-suffixOptional text after the number, such as + or %.
data-durationOptional animation length in ms (default 3500).

Keep the final number as the element's text too, so it shows when JavaScript is off.

Image lightbox

Add the class cs_lightgallery to a wrapper. Every a.cs_gallery_item inside it opens in GLightbox, and next / previous stays inside that gallery. 

<div class="cs_lightgallery">
  <a href="assets/img/photo-large.webp" class="cs_gallery_item">
    <img src="assets/img/photo.webp" alt="Describe the photo">
  </a>
</div>

FAQ accordion

Each question is a <button class="cs_accordion_head"> followed by a .cs_accordion_body, inside a .cs_accordion. Add the class active to a .cs_accordion to open it by default. aria-expanded is updated for screen readers.

Video pop-up

Any link with the class cs_video_open opens its href in a pop-up. Use a YouTube embed URL: 

<a href="https://www.youtube.com/embed/VIDEO_ID" class="cs_video_open">Play video</a>

Esc or a click outside the video closes it.

Page Effects

Preloader

The "DREAMDAY" loading screen fades out when the page is ready. To remove it, delete the cs_preloader block at the top of each page.

Back to top

The cs_scrolltop_btn button appears after 350px of scrolling.

Scroll animations (AOS)

Add data-aos="fade-up" (or fade-down, fade-right, …) to any element. The options are in aosInit() in main.js. Animations are off when the visitor prefers reduced motion.

Smooth scrolling

Lenis smooths mouse-wheel scrolling on desktop. It is skipped under reduced motion. To turn it off, delete smoothScroll(); in main.js.

Forms & Map

Contact form

The contact form sends messages with Web3Forms (free, no server code needed).

  1. Go to web3forms.com, enter your email address and copy the access key they send you.
  2. Open contact.html and replace YOUR_ACCESS_KEY_HERE: 
    <input type="hidden" name="access_key" value="YOUR_ACCESS_KEY_HERE">
  3. Upload the page and send a test message. The result shows under the button.
Until a key is added, the form shows "Form is not configured yet" instead of sending.

Newsletter form

Newsletter forms use action="#" and show a "Thank you for subscribing!" message in the demo. Connect them to your email service (Mailchimp, Brevo, …) by replacing the action URL and field names with the ones your provider gives you; the demo message then turns off automatically.

Map

In Google Maps, choose Share → Embed a map, copy the src URL and paste it into the <iframe> in contact.html.

Accessibility

The template is built to be usable with a keyboard and screen reader:

  • "Skip to main content" link and visible focus outlines on every control.
  • Mobile menu, FAQ, slider arrows and video pop-up work with the keyboard. Esc closes the menu and the video.
  • Every image has alt text and every icon-only control has an aria-label.
  • Animations are reduced or removed when the visitor asks for reduced motion.
  • Pages stay readable when JavaScript is turned off.

When you edit the template, please keep these habits:

  • Keep one <h1> per page and do not skip heading levels.
  • Give every form field a <label> (use visually-hidden to hide it visually).
  • Describe new images in alt.

Browser Support

DreamDay supports the current versions of Chrome, Edge, Firefox, Safari and Opera, on desktop and mobile.

Internet Explorer is not supported.

Troubleshooting

The map, video or contact form does not work.

They need the page to be served over http:// or https://, not opened as a file. Use a local server such as VS Code Live Server, or upload to your hosting.

The contact form says "Form is not configured yet".

Add your Web3Forms access key in contact.html. See Forms & Map.

My CSS changes disappeared.

Compiling the SCSS overwrites style.css. Make the change in the matching .scss file instead, or stop using the SCSS build. See Editing the SCSS.

I edited the SCSS but nothing changes in the browser.

The browser only reads assets/css/style.css, so the SCSS has to be compiled again after every change. Check these in order:

  1. Is the compiler running? With Live Sass Compiler, the VS Code status bar must say Watching.... If it says Watch Sass, click it, then save your .scss file again (Ctrl+S). It only compiles files you save inside VS Code. With npm, keep npm run watch:css running in a terminal.
  2. Did the compile fail? A typo in the SCSS stops the compile, and style.css keeps the old styles. Look for the error in the terminal, or in VS Code under View > Output > Live Sass Compile.
  3. Is the output going to the right file? Live Sass Compiler must save to /assets/css. Otherwise it writes a different style.css that the pages never load.
  4. Is the browser showing an old copy? Press Ctrl+F5 (Cmd+Shift+R on Mac) to reload without the cache.

Still stuck? Run npm run build:css once. It compiles everything fresh and prints any error. To make sure it worked, open style.css and search for the value you changed.

The page is stuck in dark mode or RTL.

The switcher saves the choice in the browser. Use the switcher again, open the page with ?theme=light or ?dir=ltr, or clear the site data in your browser.

A new image does not show.

Check the file name and extension. On most servers names are case-sensitive: Photo.webp and photo.webp are different files.
